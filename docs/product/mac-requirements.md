# 知声卡 macOS 版需求

状态：已确认

## 1. 产品定位

知声卡 macOS 版是一个本地优先的卡片管理与浮动学习工具。

用户通过主窗口管理卡组、导入导出数据并配置偏好；学习过程在唯一的、始终置顶的浮动窗口中进行。

macOS 与 Android 使用相同的 JSON 数据格式，但采用适合桌面端的窗口、鼠标和全局快捷键交互。

当前版本只支持 JSON 手动交换数据，不提供账号、iCloud 或网络自动同步。

## 2. 主窗口

主窗口是内容管理和设置中心，不直接承担学习流程。

主窗口包含以下区域：

- 卡组列表
- JSON 导入与导出
- 浮动窗口设置
- 全局快捷键设置
- 语音与自动学习设置

### 2.1 卡组列表

卡组列表显示：

- 卡组名称
- 卡组说明
- 卡片数量
- 当前学习位置
- 当前是否正在浮动窗口中学习

用户可以：

- 新建卡组
- 编辑卡组名称和说明
- 删除卡组
- 查看卡片列表
- 选择卡组并在浮动窗口中打开
- 将现有浮动窗口切换到另一个卡组

同一时间只能有一个卡组处于浮动学习状态。

### 2.2 卡片管理

用户可以在卡组中：

- 新建卡片
- 编辑卡片
- 删除卡片
- 调整卡片顺序

每张卡片包含：

- `title`：标题，必填
- `content`：正文，必填
- `speechText`：朗读和跟读文本，可选；为空时使用 `content`
- `memoryTip`：快速记忆点，可选

删除卡组和卡片前必须二次确认。

### 2.3 JSON 导入

macOS 与 Android 共用 `docs/reference/import-format.md` 定义的 JSON 格式和校验规则。

导入要求：

- 文件使用 UTF-8 编码
- 单个文件表示一个卡组
- 文件最大 2 MiB
- 每个卡组包含 1 到 1000 张卡片
- 先完整解析和校验，再通过单一事务写入
- 任意字段错误时拒绝整个文件
- 未知字段忽略
- 重复内容通过规范化内容的 SHA-256 指纹识别

重复导入相同内容时打开已有卡组；同名但内容不同时，经用户确认后创建新卡组。

### 2.4 JSON 导出

用户可以将任意卡组导出为 Android 兼容的 UTF-8 JSON 文件。

导出内容只包含：

- 卡组名称和说明
- 按当前顺序排列的卡片
- 卡片的 `title`、`content`、`speechText` 和 `memoryTip`

导出不包含内部 ID、时间戳、学习位置、学习记录或识别结果。

## 3. 浮动学习窗口

应用只创建一个浮动学习窗口。该窗口同一时间只显示一个卡组，并始终位于普通应用窗口之上。

### 3.1 打开与切换

用户在主窗口选择卡组后：

1. 保存旧卡组的当前位置。
2. 停止旧卡组的朗读、识别和自动翻页任务。
3. 使旧语音操作的 `operationId` 失效。
4. 将当前学习卡组切换为新卡组。
5. 恢复新卡组保存的当前位置。
6. 将已有浮动窗口带到前台。

如果浮动窗口尚未创建，则创建该窗口；如果已经存在，则复用现有窗口，不创建第二个窗口。

### 3.2 卡片显示

正面显示：

- 卡片标题 `title`
- 卡片正文 `content`

背面显示：

- 快速记忆点 `memoryTip`
- `memoryTip` 为空时显示“暂无快速记忆点”

`speechText` 不直接显示，只用于朗读和跟读；为空时使用 `content`。

切换卡片或卡组后显示正面。翻面状态不持久化，重新打开浮动窗口时从正面开始。

### 3.3 窗口行为

浮动窗口需要：

- 始终置顶
- 支持鼠标拖动
- 保存并恢复窗口位置
- 保存并恢复窗口尺寸
- 可选择是否显示在所有桌面空间
- 可选择是否显示上一张、翻面和下一张按钮
- 关闭浮动窗口时不退出整个应用
- 应用重新启动时可按设置恢复浮动窗口

## 4. 学习模式

macOS 支持与 Android 一致的三种学习模式。

### 4.1 手动学习

用户通过浮动窗口按钮、鼠标或全局快捷键：

- 查看正面和背面
- 切换上一张或下一张
- 主动开始或停止朗读

切换到下一张时保存当前位置；切换卡片后回到正面。

### 4.2 自动跟读

自动跟读流程：

1. 朗读当前卡片的目标文本。
2. 朗读完成后开始收音。
3. 将识别文字与目标文本匹配。
4. 匹配完成后停止收音并保存完成记录。
5. 显示卡片背面的快速记忆点。
6. 等待自动翻页延迟。
7. 切换到下一张并重新开始。

目标文本优先使用 `speechText`，为空时使用 `content`。

### 4.3 自动播放

自动播放流程：

1. 朗读当前卡片的目标文本。
2. 等待真实朗读完成事件。
3. 显示卡片背面的快速记忆点。
4. 等待自动翻页延迟。
5. 切换到下一张并继续朗读。

自动播放不使用麦克风，也不产生跟读完成记录。

### 4.4 语音安全规则

- 每次语音操作必须创建新的 `operationId`。
- 只有与当前 `operationId` 一致的回调才能改变状态。
- 暂停、切卡、切换卡组、切换模式和关闭窗口时，先使旧 ID 失效，再停止语音资源。
- 朗读完成后才能开始收音。
- 麦克风权限被拒绝时，应用仍可使用手动学习和自动播放。
- 应用不保存原始录音和完整识别文字。

## 5. 全局快捷键

全局快捷键在用户使用其他应用时仍然生效。

默认快捷键：

| 操作 | 默认快捷键 |
|---|---|
| 上一张 | `Control + Option + ←` |
| 翻面 | `Control + Option + Space` |
| 下一张 | `Control + Option + →` |

用户可以在主窗口中：

- 查看当前快捷键
- 录制新的快捷键组合
- 检测快捷键注册冲突
- 恢复默认快捷键

全局快捷键必须包含至少一个修饰键，不能使用无修饰键的普通字符、空格或方向键。

没有选择卡组时，学习快捷键不执行切卡操作。浮动窗口关闭但已有当前卡组时，学习快捷键可以重新打开浮动窗口并执行操作。

应用只注册配置好的快捷键，不监听或保存用户的其他键盘输入。

## 6. 设置

### 6.1 浮动窗口设置

用户可以配置：

- 窗口宽度
- 窗口高度
- 背景透明度
- 文字大小
- 是否显示操作按钮
- 是否显示在所有桌面空间
- 是否允许鼠标拖动
- 启动应用时是否恢复浮动窗口

### 6.2 学习与语音设置

用户可以配置：

- 默认学习模式
- 朗读速度
- 自动翻页延迟

### 6.3 设置行为

- 设置保存在本机。
- 修改设置后尽可能立即应用到已打开的浮动窗口。
- 窗口位置和尺寸在移动或调整结束后保存。
- 用户可以恢复默认设置。
## 7. 本地数据与生命周期

应用在本机保存：

- 卡组与卡片
- 卡片顺序
- 每个卡组的当前学习位置
- 当前选择的卡组
- 学习记录
- 用户设置
- 浮动窗口的位置和尺寸
- 自定义全局快捷键

删除卡组时级联删除其卡片、学习位置和相关记录。

切换卡组、关闭浮动窗口和退出应用前，需要保存当前学习位置并停止朗读、识别和自动翻页任务。

应用冷启动时：

1. 打开主窗口。
2. 读取本地卡组和设置。
3. 默认不自动开始朗读或收音。
4. 只有启用“启动时恢复浮动窗口”且存在有效当前卡组时，才恢复浮动窗口。
5. 恢复浮动窗口后仍保持暂停，等待用户主动继续。

## 8. 第一版验收标准

第一版完成时应满足：

- 可以手动创建、编辑、删除和排序卡组及卡片。
- 可以导入和导出 Android 兼容 JSON。
- 数据在应用重新启动后仍然存在。
- 卡组列表可以选择当前学习卡组。
- 同一时间最多存在一个浮动学习窗口。
- 切换卡组时复用现有浮动窗口。
- 浮动窗口始终置顶，并能保存位置和尺寸。
- 全局快捷键在其他应用处于前台时仍能控制学习。
- 三种学习模式都可以运行。
- TTS、跟读识别和自动翻页遵守 `operationId` 安全规则。
- 麦克风不可用时仍可使用手动学习和自动播放。
- 应用不会保存原始录音或完整识别文本。
- 当前版本不依赖账号、云同步或业务后端。
